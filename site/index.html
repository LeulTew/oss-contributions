How updates and historical records work

GitHub Actions reads the allowlisted public records on a roughly 15-minute schedule. Runs can be delayed or dropped; GitHub disables public-repository schedules after 60 days without repository activity. This page checks the published JSON every five minutes while visible. Refresh data retrieves that published snapshot; it does not trigger upstream CI or force a new GitHub API collection.

Merged and closed records are retained as historical observations rather than repeatedly polled. If collection fails, the last verified record is labeled stale; if no evidence is available, CI is unknown. An observation older than 45 minutes is labeled delayed for active work. Curated context is separately dated and may describe earlier CI conditions.
